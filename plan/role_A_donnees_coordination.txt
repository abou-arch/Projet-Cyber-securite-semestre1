1. LE PROJET EN BREF
--------------------------------------------------------------------------------
But : prédire la famille d'un malware à partir de ses caractéristiques statiques
(EMBER2024, 2568 features par fichier), puis expliquer quelles caractéristiques
comptent le plus (analyse de l'importance des features).

Déjà fait : l'installation du dataset (branche Abou, voir README.md).
  python -m malware_family.download   archives Win32 vérifiées (SHA-256)
  python -m malware_family.prepare    X et y prêts pour scikit-learn (10 familles)
  python -m malware_family.dataset    vérification de l'installation

Répartition des rôles :
  Rôle A (toi) : données, exploration, outils communs, coordination du rapport.
  Rôle B       : modèles et évaluation des performances.
  Rôle C       : importance des features et interprétation.
  Chacun rédige ses sections du rapport ; la soutenance se prépare à trois.

PHASE 1 - EXPLORATION ET OUTILS COMMUNS (semaines 1-2)
[ ] notebooks/01_exploration.ipynb :
    - effectifs par famille, train et test : les familles sont-elles équilibrées ?
      -> figure en barres ;
    - nombre d'échantillons par semaine (colonne first_seen de meta_*.csv) ;
    - distribution de family_confidence (confiance de l'étiquette) ;
    - features constantes (sklearn VarianceThreshold) : combien, dans quels
      groupes ? -> à transmettre à B ;
    - malwares du test d'autres familles : test_malware_other_families
      dans dataset_info.json.
[ ] notebooks/02_features.ipynb : comparer les familles sur des features lisibles
    (boîtes à moustaches) :
      general_size, general_entropy, section_count, section_entropy_max,
      imports_library_count, imports_function_count, strings_numstrings,
      strings_pattern_url, strings_pattern_ipv4_addr, authenticode_num_certs,
      richheader_pairs, pefilewarnings_count.
[ ] scripts/hash_lookup.py, pour C : retrouver les vrais noms derrière une colonne
    hachée (…_hashNN). C'est la même formule que scikit-learn :
        from sklearn.utils import murmurhash3_32
        case = abs(murmurhash3_32(texte, seed=0)) % n
    Exemples :
      imports_function_hashNNNN  texte = "kernel32.dll:VirtualAlloc"
                                 (bibliothèque en minuscules + ":" + fonction), n = 1024
      imports_library_hashNNN    texte = "kernel32.dll" (en minuscules), n = 256
      section_size_hashNN        texte = nom de la section, ex. ".text", n = 50
      exports_function_hashNNN   texte = nom de la fonction exportée, n = 128
    Les noms se lisent dans les lignes JSON des archives (modules zipfile et json),
    ex. champ "imports" : {"KERNEL32.dll": ["VirtualAlloc", ...]}.
    Plusieurs noms peuvent tomber dans la même case : les lister tous.
