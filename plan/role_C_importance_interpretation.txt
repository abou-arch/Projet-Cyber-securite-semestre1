1. LE PROJET EN BREF
--------------------------------------------------------------------------------
But : prédire la famille d'un malware à partir de ses caractéristiques statiques
(EMBER2024, 2568 features par fichier), puis expliquer quelles caractéristiques
comptent le plus (analyse de l'importance des features).

Déjà fait : l'installation du dataset (branche Abou, voir README.md).
  python -m malware_family.download   archives Win32 vérifiées (SHA-256)
  python -m malware_family.prepare    X et y prêts pour scikit-learn (10 familles)
  python -m malware_family.dataset    vérification de l'installation

Répartition des rôles :
  Rôle A       : données, exploration, outils communs, coordination du rapport.
  Rôle B       : modèles et évaluation des performances.
  Rôle C (toi) : importance des features et interprétation.
  Chacun rédige ses sections du rapport ; la soutenance se prépare à trois.

3. MES TÂCHES (RÔLE C)
--------------------------------------------------------------------------------

PHASE 0 - INSTALLATION (commune, 1 à 2 jours)
[ ] Récupérer le code : git pull sur la branche Abou, créer et activer un venv,
    puis pip install -r requirements.txt
[ ] Lancer python -m pytest : tous les tests doivent passer.
[ ] Préparer les données hors de tout dossier synchronisé (OneDrive, iCloud...),
    avec exactement les mêmes commandes pour les trois (mêmes données partout) :
      python -m malware_family.download --dest C:\ember2024\raw
      python -m malware_family.prepare --data-dir C:\ember2024\raw --out-dir C:\ember2024\processed\Win32_top10
      python -m malware_family.dataset C:\ember2024\processed\Win32_top10
    (macOS / Linux : mêmes commandes avec un dossier comme ~/ember2024)
[ ] Comparer dataset_info.json entre les trois machines : mêmes familles,
    mêmes effectifs.

PHASE 1 - COMPRENDRE LES FEATURES ET PRÉPARER LES OUTILS (semaines 1-2)
[ ] Lire le tableau « feature du sujet -> groupe EMBER2024 » du README, et
    malware_family/ember_features.py (FEATURE_GROUPS, feature_names(),
    feature_groups()).
[ ] scripts/importance.py : écrire les fonctions de calcul (voir phase 2) et les
    mettre au point dès J1 sur le modèle de base de B, avec un petit échantillon
    (quelques milliers de lignes) pour aller vite.
[ ] J2 : prendre en main scripts/hash_lookup.py de A, qui donne les vrais noms
    (DLL, fonctions, sections) derrière les colonnes hachées (…_hashNN).

PHASE 2 - IMPORTANCE DES FEATURES (semaines 3-4)
[ ] Importance « MDI » du RandomForest (model.feature_importances_) : top 30, et
    somme par groupe avec feature_groups().
    Limite à signaler : le MDI favorise les features continues aux nombreuses valeurs.
[ ] Importance par permutation sur la validation ou le test, avec le F1 macro :
    - PAR GROUPE (12 groupes) : permuter toutes les colonnes d'un groupe en même
      temps, recalculer le F1 macro et comparer au score d'origine. Petite boucle
      maison : permutation_importance de scikit-learn ne sait pas regrouper des
      colonnes. Cela répond directement au sujet : imports, taille, sections,
      chaînes ou fréquence des octets, qu'est-ce qui compte le plus ?
    - Feature par feature (sklearn.inspection.permutation_importance,
      scoring="f1_macro", n_repeats=5) seulement pour les ~50 meilleures features
      du MDI : sur les 2568 colonnes, ce serait beaucoup trop long.
[ ] Ablation, avec les paramètres de modèle de B (HistGradientBoosting, plus rapide) :
    réentraîner avec UN seul groupe, puis avec tous les groupes SAUF un
    -> tableau des F1 macro.
[ ] Traduire les colonnes hachées importantes en noms réels (hash_lookup.py de A).
[ ] Importance par famille : pour chaque famille, permutation par groupe en
    « une famille contre les autres », ou profil moyen des features clés.
[ ] J3 : relancer tous les calculs sur le modèle final de B ; enregistrer
    results/importances.csv et les figures (results/figures/C_*.png).
[ ] Transmettre à B les groupes et features les plus importants
    (il testera un modèle réduit).

PHASE 3 - INTERPRÉTATION ET LIMITES (semaine 5)
[ ] Relier les features importantes à ce que l'on sait des familles (descriptions
    publiques : Malpedia, rapports d'éditeurs de sécurité), par exemple :
    entropie élevée et packing, imports réseau ou de chiffrement, signature
    absente. Sans jamais télécharger d'échantillon.
[ ] Expliquer avec B les confusions de sa matrice de confusion.
[ ] Limites à discuter :
    - hashing : plusieurs noms partagent une même colonne ;
    - features corrélées : la permutation sous-estime leur importance ;
    - étiquettes bruitées (ClarAVy ; « familles » génériques comme wacatac) ;
    - dérive temporelle ; familles absentes du top 10 ;
    - plafond de 10 000 échantillons par famille.

PHASE 4 - RAPPORT ET SOUTENANCE (semaine 6)
[ ] Rédiger mes sections : Importance des features, Discussion et limites
    (avec B) ; transmettre à A pour l'intégration.
[ ] Relire les sections de A (B relit les miennes).
[ ] Diapositives : importance des features et limites ; répéter à trois.
