--------------------------------------------------------------------------------

(EMBER2024, 2568 features par fichier), puis expliquer quelles caractéristiques
comptent le plus (analyse de l'importance des features).

  python -m malware_family.dataset    vérification de l'installation

PHASE 1 - COMPRENDRE LES FEATURES (semaines 1-2)
[ ] Lire le tableau « feature du sujet -> groupe EMBER2024 » du README, et
    malware_family/ember_features.py (FEATURE_GROUPS, feature_names()).
[ ] notebooks/02_features.ipynb : comparer les familles sur des features lisibles
    (boîtes à moustaches) :
      general_size, general_entropy, section_count, section_entropy_max,
      imports_library_count, imports_function_count, strings_numstrings,
      strings_pattern_url, strings_pattern_ipv4_addr, authenticode_num_certs,
      richheader_pairs, pefilewarnings_count.
[ ] scripts/hash_lookup.py : retrouver les vrais noms derrière une colonne hachée
    (…_hashNN). C'est la même formule que scikit-learn :
        from sklearn.utils import murmurhash3_32
        case = abs(murmurhash3_32(texte, seed=0)) % n
    Exemples :
      imports_function_hashNNNN  texte = "kernel32.dll:VirtualAlloc"
                                 (bibliothèque en minuscules + ":" + fonction), n = 1024
      imports_library_hashNNN    texte = "kernel32.dll" (en minuscules), n = 256
      section_size_hashNN        texte = nom de la section, ex. ".text", n = 50
      exports_function_hashNNN   texte = nom de la fonction exportée, n = 128
    Les noms se lisent dans les lignes JSON des archives (modules zipfile et json),
    ex. champ "imports" : {"KERNEL32.dll": ["VirtualAlloc", ...]}.
    Plusieurs noms peuvent tomber dans la même case : les lister tous.
[ ] Dès J1 : premier calcul d'importance sur le modèle de base de A, sur un
    petit échantillon, pour mettre au point le code.

PHASE 2 - IMPORTANCE DES FEATURES (semaines 3-4)
[ ] Importance « MDI » du RandomForest (model.feature_importances_) : top 30, et
    somme par groupe avec feature_groups() de malware_family.ember_features.
    Limite à signaler : le MDI favorise les features continues aux nombreuses valeurs.
[ ] Importance par permutation sur la validation ou le test, avec le F1 macro :
    - PAR GROUPE (12 groupes) : permuter toutes les colonnes d'un groupe en même
      temps, recalculer le F1 macro et comparer au score d'origine. Petite boucle
      maison : permutation_importance de scikit-learn ne sait pas regrouper des
      colonnes. Cela répond directement au sujet : imports, taille, sections,
      chaînes ou fréquence des octets, qu'est-ce qui compte le plus ?
    - Feature par feature (sklearn.inspection.permutation_importance,
      scoring="f1_macro", n_repeats=5) seulement pour les ~50 meilleures features
      du MDI : sur les 2568 colonnes, ce serait beaucoup trop long.
[ ] Ablation, avec les paramètres de modèle de A : réentraîner avec UN seul groupe,
    puis avec tous les groupes SAUF un -> tableau des F1 macro.
[ ] Traduire les colonnes hachées importantes en noms réels (hash_lookup.py).
[ ] Importance par famille : pour chaque famille, permutation par groupe en
    « une famille contre les autres », ou profil moyen des features clés.
[ ] Enregistrer results/importances.csv et les figures dans results/figures/.

PHASE 3 - INTERPRÉTATION ET LIMITES (semaine 5)

[ ] Expliquer avec A les confusions de sa matrice de confusion.
[ ] Limites à discuter :

    - dérive temporelle ; familles absentes du top 10 ;
    - plafond de 10 000 échantillons par famille.
