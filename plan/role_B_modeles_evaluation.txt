1. LE PROJET EN BREF
--------------------------------------------------------------------------------
But : prédire la famille d'un malware à partir de ses caractéristiques statiques
(EMBER2024, 2568 features par fichier), puis expliquer quelles caractéristiques
comptent le plus (analyse de l'importance des features).

Déjà fait : l'installation du dataset (branche Abou, voir README.md).
  python -m malware_family.download   archives Win32 vérifiées (SHA-256)
  python -m malware_family.prepare    X et y prêts pour scikit-learn (10 familles)
  python -m malware_family.dataset    vérification de l'installation

Répartition des rôles :
  Rôle A       : données, exploration, outils communs, coordination du rapport.
  Rôle B (toi) : modèles et évaluation des performances.
  Rôle C       : importance des features et interprétation.
  Chacun rédige ses sections du rapport ; la soutenance se prépare à trois.

3. MES TÂCHES (RÔLE B)
--------------------------------------------------------------------------------

PHASE 0 - INSTALLATION (commune, 1 à 2 jours)
[ ] Récupérer le code : git pull sur la branche Abou, créer et activer un venv,
    puis pip install -r requirements.txt
[ ] Lancer python -m pytest : tous les tests doivent passer.
[ ] Préparer les données hors de tout dossier synchronisé (OneDrive, iCloud...),
    avec exactement les mêmes commandes pour les trois (mêmes données partout) :
      python -m malware_family.download --dest C:\ember2024\raw
      python -m malware_family.prepare --data-dir C:\ember2024\raw --out-dir C:\ember2024\processed\Win32_top10
      python -m malware_family.dataset C:\ember2024\processed\Win32_top10
    (macOS / Linux : mêmes commandes avec un dossier comme ~/ember2024)
[ ] Comparer dataset_info.json entre les trois machines : mêmes familles,
    mêmes effectifs.

PHASE 1 - PREMIERS MODÈLES (semaines 1-2)
[ ] scripts/train.py : modèles de référence, évalués sur le test :
    - DummyClassifier(strategy="most_frequent") : le plancher à battre ;
    - RandomForestClassifier(n_estimators=100, n_jobs=-1, random_state=0) ;
    - HistGradientBoostingClassifier(random_state=0,
          categorical_features=CATEGORICAL_FEATURES)
      (CATEGORICAL_FEATURES vient de malware_family.ember_features).
[ ] Métriques : accuracy, balanced_accuracy, F1 macro (métrique principale : les
    familles n'ont pas toutes la même taille) et classification_report.
[ ] J1 : pousser scripts/train.py dès que le RandomForest fonctionne, pour que C
    puisse reproduire le modèle et commencer l'importance des features.
[ ] Tenir compte des constats de A : déséquilibre des familles, features
    constantes (inutiles, peuvent être retirées).

PHASE 2 - OPTIMISATION DES MODÈLES (semaines 3-4)
[ ] Validation temporelle : les lignes de X_train sont triées par date. Garder les
    15 % les plus récentes pour la validation, le reste pour l'entraînement.
    Ne JAMAIS régler les paramètres en regardant le test.
[ ] Régler deux modèles (quelques combinaisons bien choisies suffisent) :
    - RandomForest : n_estimators, max_depth, min_samples_leaf, max_features,
      class_weight="balanced" ;
    - HistGradientBoosting : learning_rate, max_iter, max_leaf_nodes,
      l2_regularization, class_weight="balanced" (scikit-learn >= 1.2).
[ ] (Option) Une référence linéaire : StandardScaler + LogisticRegression.
[ ] Choisir le modèle final sur la validation, le réentraîner sur tout le train,
    puis l'évaluer UNE seule fois sur le test.
[ ] J3 : enregistrer et partager :
    - models/best_model.joblib (joblib.dump ; trop gros pour git) ;
    - results/metrics.json : scores, paramètres, temps d'entraînement ;
    - results/predictions_test.csv : sha256, famille réelle, famille prédite,
      probabilité maximale.

PHASE 3 - ÉVALUATION APPROFONDIE (semaine 5)
[ ] Matrice de confusion normalisée (ConfusionMatrixDisplay.from_predictions,
    normalize="true") : quelles familles sont confondues ? À expliquer avec C.
[ ] F1 par famille en fonction du nombre d'exemples d'entraînement.
[ ] Dérive temporelle : F1 macro semaine par semaine sur le test (first_seen).
    Les performances baissent-elles avec le temps ?
[ ] Bruit des étiquettes : réentraîner sur la variante --min-confidence 0.5
    préparée avec la commande de A, puis comparer les scores.
[ ] Stabilité : 3 valeurs de random_state -> moyenne et écart-type des scores.
[ ] Modèle réduit aux groupes ou features les plus importants selon C :
    le score baisse-t-il ? Le temps d'entraînement diminue-t-il ?
[ ] (Bonus) Rejet des prédictions incertaines : si la probabilité maximale est
    sous un seuil, répondre « inconnu » ; tracer la précision selon la couverture.

PHASE 4 - RAPPORT ET SOUTENANCE (semaine 6)
[ ] Rédiger mes sections : Méthodologie (modèles, validation, métriques) et

[ ] Relire les sections de C (C relit celles de A, A relit les miennes).
[ ] Diapositives : modèles et résultats ; répéter la soutenance à trois.
